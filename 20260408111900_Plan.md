## 1. ФИЛОСОФИЯ И ПОЗИЦИОНИРОВАНИЕ (The "Why")

### 1.1 Личный бренд и миссия

* **Кто делает:** Соло-разработчик, который сам играет в группе.

* **Проблема:** Хаос в мессенджерах, бумажки на репетициях, потерянные BPM.

* **Решение:** Простой, реактивный инструмент «от своих для своих».

* **Почему донатить:** Ты не корпорация. Ты — мастер, который строит инструмент. Донат на Ko-fi — это способ сказать «спасибо» человеку, а не покупка лицензии у гиганта.

## 2. ФАЗА 1: ТЕХНИЧЕСКАЯ «ПОЛИРОВКА» (Flutter & Firebase)

Здесь мы создаем тот самый «вау-эффект» для первого пользователя.

### 2.1 Умная автоматизация (The Magic)

* **Интеграция API GetSongBPM:** Пакеты `http` + `flutter_typeahead`. При вводе названия песни «Wonderwall» -> выпадающий список -> автозаполнение BPM (87) и Key (F#m).

* **Failsafe Mode:** Если API недоступно, пользователь просто продолжает ввод вручную. Никаких блокирующих ошибок.

### 2.2 Stage-Ready UX (Для сцены)

* **Wakelock:** Пакет `wakelock`. Экран горит всегда, пока открыт сет-лист.

* **High-Contrast Dark Theme:** Глубокий черный фон. Музыкант не должен слепнуть в темном клубе.

* **Touch Targets:** Увеличение всех кнопок навигации. Нажать «Next Song» должно быть легко даже потным пальцем или медиатором.

* **Real-time Sync:** Firestore-оптимизация. Задержка обновления между устройствами должна быть < 500мс.

### 2.3 Путь пользователя (Onboarding)

* **Try Demo:** Вход без регистрации (Anonymous Auth). Пользователь сразу видит готовый сет-лист «The Beatles Cover Band».

* **Upsell в регистрацию:** Кнопка «Save this setlist to your account» в шапке.
