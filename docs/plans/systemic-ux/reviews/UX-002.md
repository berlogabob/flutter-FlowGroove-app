# UX-002 — global/context Menu: accepted source review

Independent controller review, 2026-10-25. Luna draft retained in its isolated worktree; this report corrects its orientation and scope claims. Evidence class: CODE, not new DEVICE or human usability evidence.

## Confirmed source behavior

- `lib/screens/main_shell.dart:15-39,44-54`: four visible root tabs plus Menu; Profile remains the fifth router branch. Root-pushed tools live outside this shell.
- `main_shell.dart:76-84,230-240`: pushed mode uses branch observer depth or non-root URI; contextual menu selection switches from root `forLocation` to `pushedEntryFor`. Implementation of that registry and full route coverage were not inspected here.
- Portrait root (`main_shell.dart:220-227`) always has Menu. Portrait child (`:207-217`) hides Menu when no contextual items exist. `lib/widgets/bottom_nav_or_action_bar.dart:164-176` confirms the null callback renders an empty slot.
- **Orientation distinction:** landscape rail (`main_shell.dart:153-205`, especially `:187-198`) always renders a Menu action, including pushed mode without items. The draft's claim of identical visibility across orientations was incorrect. Empty child-menu usability was not exercised; this is a conditional CODE observation, not a new device defect.
- `main_shell.dart:243-256` passes contextual items and `showProfileRow: !_pushed`. `lib/widgets/app_menu_sheet.dart:103-109` appends Profile and Settings only when that flag is true. Therefore these global rows are absent from the shell's pushed sheet; this does not prove there is no other route to Settings/Profile in the app.
- `app_menu_sheet.dart:185-190,232-240` preserves existing Settings named-route push and Profile branch navigation. `:130-160` keeps trailing rows open; non-trailing actionable rows close before their callback.

## Classification and before → candidate after

Confirmed: the same Menu label denotes mixed global/context actions at roots and contextual-only actions on children; portrait/landscape differ for empty child menus. No router failure, data loss or observed human confusion established. Comments describing the former Profile tab are historical rationale, not validation.

Hypothesis: discovering global destinations from a child may be harder. Human task success and Happiness remain unset. Do not implement global rows everywhere merely from this hypothesis.

Before: a root Menu mixes contextual items with Profile/Settings; a child sheet excludes global rows. Candidate after, **only after DESIGN-01 approval**: specify a consistent global-versus-context contract and change the minimal shell assembly while preserving routes/providers/Mono Pulse. No production fix is accepted by this review. If the approved design needs multiple production files, register separate bounded slices before editing.

## Public acceptance seam and gaps

Use rendered routed MainShell in portrait/landscape with root, child-with-items and child-without-items states; verify visible Menu, sheet contents and retained navigation through user actions. Constructor parameters are not a sufficient behavior seam. Existing tests/fixtures must be inspected before implementation; no new tests are authorized at an internal seam by this source review.

Read completely: the three named production files. No builds, device navigation, account operations, route/registry implementation audit, permissions audit or human testing. UX-002 remains open; UX-002-I is blocked on DESIGN-01.
